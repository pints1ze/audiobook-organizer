## Where things stand
- **Locally:** the API runs on port 5070 (`scripts/start-api.ps1`) with SQLite at `<repo>/data/audiobooks.db`. The React client runs on port 5173 (`scripts/start-client.ps1`) and shows the API and database status.
- **Docker:** `docker compose up --build` serves both on port 8080, with `/data`, `/incoming` and `/library` mounted from `./docker/` by default.
- **Tag safety:** proven by tests. MP3 writes go through TagLibSharp and M4B writes through an ffmpeg `-c copy` remux; chapters and audio survive both. `ChapterReader` reads chapters from both formats. The image ships ffmpeg/ffprobe 6.1.
- **Settings API:** `GET`/`PUT /api/settings` stores the validated incoming and library paths and the keep-source toggle in SQLite (`ApplicationSetting`). The Settings page (`/settings`) edits them, inside a layout with nav, a skip link and a not-found page.
- **Scan inventory:** `ScanService` records every MP3 and M4B under incoming in `AudioFile`, with a `ScanRun` per scan. It skips unchanged files and records unreadable ones, retrying them on the next scan. `POST /api/scans` runs one background scan at a time, `GET /api/scans/latest` shows progress, and `GET /api/dashboard` returns the paths and counts. The dashboard shows the directories, last scan and counts, with a "Scan incoming" button and live progress. The whole flow is verified on Windows dev and in Docker (Linux).
- **Grouping engine:** the pure `GroupingEngine.Group` proposes book groups from scanned file facts, with confidence, evidence and an estimated title and author; scenarios A–E pass. Every completed scan regroups the files it saw into `FileGroup` and `FileGroupFile` (replacing all groups), and `GET /api/groups` lists the groups (least confident first) and the unresolved files. The Incoming page (`/incoming`) shows them with confidence and evidence.
- **Corrections:** `PUT /api/groups/{id}` sets a group's title and author and marks it `UserCorrected`. Rescans keep corrected groups and their files untouched and regroup only the rest. The Incoming page edits title and author in place and marks corrected books "Edited" (slice 14). `GET /api/groups/{id}` lists a group's files in order and `PUT /api/groups/{id}/order` reorders them (slice 15). Each Incoming row has a "Files" disclosure with keyboard-accessible Move up and Move down (slice 16). `POST /api/groups/{id}/files` moves files into a group and `POST /api/groups` creates a group from files; together they give move, merge and split (slice 17). Each Files list has checkboxes and a "Move selected to" bar that moves files to another book or a new book (slice 18). The Unresolved section has the same selection and move bar (slice 19, shared `MoveBar`). `POST /api/groups/excluded` and `POST /api/groups/unresolved` set a file's `UserState`, and `GET /api/groups` lists `excluded` (slice 20). The move bar also offers "Unresolved files" and "Excluded files", and an Excluded section sends files back (slice 21).
- **Metadata search:** `GET /api/metadata/search?keywords=` searches Audible's catalog through `AudibleClient`, a typed `HttpClient` behind `IMetadataProvider`. It returns normalized candidates (ASIN, title, authors, narrators, series, publisher, release date, language, runtime, format, cover URL) (slice 27). `MetadataSearchService` falls back to `OpenLibraryClient` when Audible fails or finds nothing; ISBN keywords search Open Library by ISBN. The response is `{ candidates, providerErrors }`: 400 for blank keywords, 502 only when every provider failed (slice 28). Tests use real responses in `docs/fixtures/audible/` and `docs/fixtures/openlibrary/` through `FakeHttpMessageHandler`. Each Incoming book links ("Find metadata") to `/books/:groupId`, which shows the book and a catalog search prefilled with its title and author, listing candidates and provider errors (slice 29). `PUT /api/groups/{id}/match` stores a picked candidate as the book's `Audiobook` + `MetadataMatch` (one current match, raw candidate JSON) and marks the group `UserCorrected`; `GET` returns it or 204 (slice 30). The book page shows the chosen match and a "Use this match" button on each result (slice 31). Each book stores metadata values in `AudiobookField` with an origin (`file`, `provider`, `user`): `GET`/`PUT /api/groups/{id}/metadata` read them and save user edits, and picking a match copies the candidate in. User values are never overwritten, a gap in the candidate keeps the old value, and Open Library never replaces Audible (slice 32). The book page's Metadata section shows each value with its origin and a "Match: …" line where the chosen match differs, and edits save only the changed fields (slice 33). `GET /api/groups/{id}/cover` lists the files with embedded covers and the chosen cover, `GET .../files/{fileId}/cover` serves an embedded JPEG or PNG, `PUT .../cover` with `{ source: "embedded", fileId }` stores it in `AudiobookCover`, and `GET .../cover/image` serves the chosen one (slice 34). `PUT .../cover` with `{ source: "provider" }` downloads the stored match's cover through `CoverDownloadClient` (https on `m.media-amazon.com` or `covers.openlibrary.org` only, type from the bytes, 502 on a failed download) (slice 35). `PUT .../cover/upload` stores an uploaded JPEG or PNG (multipart `file`, at most 10 MB, typed by its bytes), and `services/api.ts` has typed calls for all cover endpoints (slice 36). The book page's Cover section shows the chosen cover and chooses an embedded cover, the match's cover or an upload (slice 37).
- **Normalization:** `Person`/`PersonAlias` and `Genre`/`GenreAlias` store canonical people (authors and narrators), genres and their variants. `GET`/`POST /api/people`, `PUT /api/people/{id}` (replaces name and aliases) and `GET /api/people/resolve?name=` list, create, edit and resolve people by `NameKey` (whitespace, case and `Last, First` folded); a key owned by another person is a 400 (slice 38). `/api/genres` does the same for genres with `GenreKey` (`-`, `_`, `/` folded to spaces). Both go through `CanonicalNameRepository` and `CanonicalNameService` keyed by `CanonicalKind` (slice 39). `POST /api/{people|genres}/{id}/merge` with `{ fromId }` folds one entry into another: its name and aliases become aliases of the kept one (slice 40). `GET /api/{people|genres}/suggestions` lists likely duplicates (same letters; matching initials for people) with a reason, never merging them (slice 41). The People (`/people`) and Genres (`/genres`) pages list, add and edit entries with their aliases through one `NamesPage` (slice 42), and show possible duplicates and a per-row "Merge into…", each with an inline confirmation (slice 43). `GET /api/groups/{id}/people` resolves each of a book's authors and narrators to a person through the aliases on every read, or lists suggested people for unresolved names; nothing is stored (slice 46). The book page's People section shows each name as normalized or not linked, links it to a suggested person (adds an alias) or adds it as a new person, and reloads after a picked match or a metadata save (slice 47). Books have a hand-entered `genres` list in the metadata API (user values only; a pick never touches it), and `GET /api/groups/{id}/genres` resolves each genre the same way with same-letters suggestions (slice 48). The Metadata section shows and edits genres, one per line; genre errors say "entries" (slice 49). `NameLinks` (`kind` people or genres) shows the People and Genres link sections on the book page (slice 50).
- **Naming:** `NamingTemplate.Render` (in `Services/Naming/`) renders a template into a sanitized relative path with `Missing` tokens or an `Error`, and `NamingTemplate.ResolveUnder` refuses any path outside the library root (slice 44). `GET`/`PUT /api/settings` also store the directory and file templates (defaults below when unset), validated through `Render`; the Settings page edits them (slice 45). `BookTokens.For` maps a book and each file to the tokens, and `GET /api/groups/{id}/preview` shows each file's source, relative path and destination under the library in book order, with missing tokens and errors; nothing is written (slice 51). `GET /api/preview` does this for every book and flags `duplicate` destinations (ignoring case, across books) and destinations that already `exists`, with counts; the per-book preview carries the same flags (slice 52). The Preview page (`/preview`) shows the counts and every book's files From → To with their problems, and can show only books with problems (slice 53).
- **Processing:** `POST /api/jobs` with `{ groupId }` approves a book whose preview is clean (no errors, missing values, duplicate or existing destinations) into a `Queued` `ProcessingJob`, snapshotting each file's source and destination as `Pending` `ProcessingJobFile` rows, and marks the group `UserCorrected`; 400 with a reason, 404, or 409 when already queued or running. `GET /api/jobs` and `/api/jobs/{id}` read them. A hosted `ProcessingWorker` runs queued jobs one at a time: each file is copied through a `.partial` file and renamed into place, never overwriting; a failure records the reason and removes the job's copies; a job cut off by a restart is failed at startup. Sources are only read (slice 55). `TagWriter` makes each copy a tagged file: MP3 through TagLibSharp, M4B through one ffmpeg `-c copy` remux keeping chapters and other tags. It writes title/album, authors as artists and album artists, genres (canonical names when linked), year, track N of M, disc and the chosen cover; empty values keep the source's (slice 56). Each copy is read back in place (title, first artist, track, cover, chapter count, duration ±1 s); a mismatch deletes it and fails the job. When the whole job verified and keep-source is off, each unchanged source is deleted (`SourceDeleted`); a changed or undeletable source is kept with an `Error` and the job still succeeds (slice 57). Each clean book on the Preview page has an Approve button (`approveBook` in `services/api.ts`) that queues it and focuses a "Queued for processing." status, or shows the refusal (slice 58). The Jobs page (`/jobs`) lists jobs with their errors and file details, polls while any is active, and retries a book's newest failed job by approving it again; tests prove a retry leaves one copy per file (slice 59). A test-only spike shows M4B freeform atoms can be written by a TagLibSharp save followed by splicing the remuxed `chpl` back (candidate A); chapters, audio, cover and tags survive (slice 60).
- **Tests:** both test projects exist and all four checks pass.

## Decisions
- 2026-10-18: Docker (Linux), single user, no auth. Trusted LAN; overview.md's deployment wins over AGENTS.md's IIS/Entra template.
- 2026-10-18: SQLite + Dapper, not PostgreSQL. One user, one file on a mounted volume.
- 2026-10-18: TagLibSharp handles tag reading and MP3 writes.
- 2026-10-18 (slice 04, gate 3): TagLibSharp 2.3.0 corrupts the M4B `chpl` chapter atom when it saves. The developer chose ffmpeg/ffprobe, installed in the image, for M4B tag and cover writes (`-c copy`) and for M4B chapter reads. AGENTS.md is updated.
- 2026-10-18: Audible catalog search is the primary provider, with Open Library as fallback. Matches are never auto-applied.
- 2026-10-18: Sources are copied, the copy is tagged and verified, then the source is deleted. The "keep source files" setting defaults to off.
- 2026-10-18: Template syntax is `%token%`, `%token:N%` padding and `[optional]` sections only.
- 2026-10-18: Covers can come from the embedded image, a provider download or an upload. The chosen file is embedded in every output file.
- 2026-10-18: Custom tags follow Audiobookshelf conventions.
- 2026-10-18: Genres are entered by hand in v1. Provider genres come later.
- 2026-10-18 (slice 01): `.gitignore` uses `*.db*` patterns instead of `data/`, because case-insensitive git would also ignore the `Data/` source folders.
- 2026-10-18 (slice 01): There's no HTTPS, auth middleware or OpenAPI in the API.
- 2026-10-18 (slice 02): The typecheck command is `npx tsc -b --noEmit`, because Vite's root tsconfig only holds references. AGENTS.md was updated with the developer's OK.
- 2026-10-18 (slice 03): The dev database lives at `<repo>/data/` (`../../data/audiobooks.db`) and the container uses `/data/audiobooks.db`. Unknown `/api/*` paths return 404; other paths get the SPA shell.
- 2026-10-18 (slice 04): M4B chapters are read through ffprobe JSON, and fixtures are generated silence (`scripts/make-audio-fixtures.ps1`). A known-bug test guards the TagLibSharp `chpl` corruption.
- 2026-10-18 (slice 05): Settings are key/value rows in `ApplicationSetting`. The schema is `CREATE TABLE IF NOT EXISTS` in `DatabaseInitializer`, with no migration framework. Validation never writes into incoming.
- 2026-10-18 (slice 07): Duration comes from ffprobe, because TagLibSharp misreads MPEG-2 MP3 duration. Files are unchanged when size and mtime match. Rows for missing files are kept and counted.
- 2026-10-18 (slice 08): Only one scan runs at a time (409 otherwise). Runs still `Running` at startup are marked `Failed`. Dashboard counts come from the latest completed run.
- 2026-10-18 (slice 10): Grouping is deterministic and rule-based within one container folder. Confidence is the number of agreeing signals (2+ High, 1 Medium, conflict Low). Untagged root files with no shared stem are unresolved.
- 2026-10-18 (slice 11): Groups are fully replaced after each completed scan (a shortcut until phase 4). SQLite foreign keys are enforced on every connection.
- 2026-10-18 (slice 13): Any user correction marks the whole group `UserCorrected`, which freezes its membership; rescans skip its files. New columns on existing tables are added by a guarded `ALTER TABLE ... ADD COLUMN` in `DatabaseInitializer`.
- 2026-10-18 (slice 17): Merge and split aren't separate endpoints. Merge moves all of B's files into A (B is deleted when empty); split creates a user-made group (`High`, "Grouped by the user") from the chosen files.
- 2026-10-18 (slice 18, developer): An excluded file stays excluded until the user undoes it, survives rescans, and can be sent back to unresolved. Unresolved files stay unresolved across rescans.
- 2026-10-18 (slice 20): The exclude and keep-unresolved states live in `AudioFile.UserState`. The grouping engine skips any file with a state; placing a file in a group clears it, and undoing an exclude sends the file to unresolved.
- 2026-10-18 (developer): Phase 4 is reopened for its leftovers. The grouping-rule tweaks are dropped (no real-collection list). Group ids must stay stable: never reused after a group is deleted. (Done in slice 24: `FileGroup` is `AUTOINCREMENT`, and old databases are rebuilt once at startup.)
- 2026-10-18 (slice 18): A bug found by a manual check inside a slice gets its own `fix: slice NN` commit, with the developer's OK.
- 2026-10-19 (slice 27): Providers sit behind `IMetadataProvider` and throw only `MetadataProviderException`, which the API returns as a 502 problem. Search candidates aren't stored until a match is picked. The series part stays a string, and format is passed through from the provider.
- 2026-10-19 (slice 28): Providers are tried in registration order (Audible, then Open Library) and the first non-empty result wins; there's no merging. Open Library candidates leave publisher and language empty because its search data mixes print editions.
- 2026-10-19 (slice 29): The book page is keyed by group id (`/books/:groupId`); the `Audiobook` will stay one-to-one with its group, so the URL can stay.
- 2026-10-19 (slice 30): Picking a match counts as a user correction (`UserCorrected = 1`) so rescans keep it. One current `MetadataMatch` per `Audiobook`; both cascade-delete with the group. The client's candidate is validated, not re-fetched.
- 2026-10-19 (slice 32): Metadata values are one `AudiobookField` row per field (JSON value, origin, provider). In a PUT, `null` means "not sent" and `""`/`[]` is an explicit empty user value. The group title and author are a read-time `file` fallback, never stored.
- 2026-10-19 (slice 33): "Proposed" in the editor means the chosen match's value, shown only where it differs from the stored one. List fields are edited one name per line so names with commas stay whole.
- 2026-10-19 (developer): Manual completion with no match is met by slice 33's editor; no separate "complete" state.
- 2026-10-19 (slice 34): The chosen cover is stored as a BLOB in `AudiobookCover` (one per book, cascade-deleted), not as a file under `/data`. Only JPEG and PNG are accepted or served, at most 10 MB. Choosing a cover marks the group `UserCorrected`.
- 2026-10-19 (slice 35): Provider covers are downloaded only from the stored match's URL, never a URL in the request, and only over `https` from the two catalog image hosts. Only the first URL is checked, because Open Library redirects to archive.org (marked as a shortcut).
- 2026-10-19 (slice 35, developer): A flaky test is fixed, not accepted. `UnresolvedFiles` resets its selection during render, not in an effect, so an early tick isn't lost.
- 2026-10-19 (slice 38): One `Person` table for authors and narrators (role goes on the book link later). Exact-key variants resolve automatically; joining two entries or fuzzy matches are only ever suggested. A key belongs to one person, as name or alias.
- 2026-10-19 (slice 39): People and genres share one repository and service (`CanonicalKind`), with separate tables and key namespaces. Genre keys fold `-`, `_` and `/`; abbreviations like `Sci-Fi` need an alias.
- 2026-10-19 (slice 40): A merge keeps the target entry; the merged entry's name and aliases become its aliases and the entry is deleted. No undo; merges only happen on an explicit user request.
- 2026-10-19 (slice 41): Suggestions are computed on each request from the catalog (no table) by two deterministic rules: same letters and digits, and matching initials for people. `keep` is the entry with more aliases.
- 2026-10-19 (slice 42): One `NamesPage` serves both kinds (`kind` prop, keyed route); after each save the list is reloaded from the API rather than patched locally.
- 2026-10-19 (slice 43): Merges in the UI always need an inline confirmation (no modal); there is no undo.
- 2026-10-19 (slice 44): Templates allow one level of `[ ]` (no nesting). Segments are sanitized with one Windows-safe rule set on every OS, and a `/` or `\` in a value becomes `-`, never a folder. Segments are capped at 200 characters (marked as a shortcut).
- 2026-10-19 (developer): Linking a book's authors, narrators and genres to canonical entries joins phase 7, after templates in settings and before book-to-token mapping (PLAN.md updated).
- 2026-10-19 (developer): The default file template is `[%track:3%. ]%album% (%artist%)`. The directory default stays `%artist%/[%series%/Book %series-part:2% - ]%album%`.
- 2026-10-19 (slice 45): Templates are required on `PUT /api/settings` (blank is a 400, never defaulted) and validated against sample values for every token, so settings reject only structural errors; missing values and empty paths are the preview's job. The file template can't contain `/` or `\`.
- 2026-10-19 (developer, slice 46): A book's people (and later genres) link to canonical entries by resolving their stored names through the aliases on each read, with no link tables. Linking a name means adding it as an alias or creating the entry. People first; genres get a book field later. PRD updated.
- 2026-10-19 (slice 46): `GET /api/groups/{id}/metadata` origins are unchanged; the people response is where a value shows as normalized.
- 2026-10-19 (slice 47): The book page links only to suggested people or a new person, with no confirmation (undo by removing the alias on `/people`). A link sends the person's full alias list plus the name (`PUT` replaces it).
- 2026-10-19 (slice 48): Genres are a stored `AudiobookField` list with no file fallback, cleaned with the people rules (50 entries max). Book links for people and genres share `Linker(CanonicalKind)`.
- 2026-10-19 (developer, slice 51): `%artist%`/`%narrator%` render the first author/narrator (canonical name when linked); `%title%` is the book title; `%track%` is the file's position in book order (1 for a single file), and processing writes that position as the track tag.
- 2026-10-19 (slice 52): Duplicate destinations are compared ignoring case on every OS (Windows dev, possibly case-insensitive library shares). Error files are never duplicates or existing. The per-book preview builds the whole library preview (shortcut until it's slow).
- 2026-10-19 (slice 54): Approval refuses missing values as well as errors, duplicates and existing files (assumption, reversible). A job snapshots each file's destination at approval; `ProcessingJob.GroupId` is `ON DELETE SET NULL` so history outlives the group. Approving marks the group `UserCorrected`.
- 2026-10-19 (slice 55): A failed job removes only the copies it wrote (and its own `.partial`), so a retry can start clean; folders it created may stay empty (shortcut). Worker tests that need a quiet queue use a host without the hosted worker.
- 2026-10-20 (developer): Audiobookshelf compatibility isn't the tagging goal; files carry full tags for the developer's own renaming and regrouping, modelled on their Mp3tag Audible script (`mp3tagscipt.src`). Narrator stays `composer`.
- 2026-10-19 (slice 58): Retrying a failed book means approving it again (fresh destinations from the current preview); the failed job stays as history. Assumption, reversible.
- 2026-10-19 (slice 57): Copies are read back at their destination (the readers need the audio extension), so a copy is briefly visible before it verifies. Sources are deleted only after the whole job verified; a changed or undeletable source is kept with an error, not a failed job. Duration tolerance is 1 s.
- 2026-10-19 (slice 56): Tags come from the book's metadata at run time; only destinations are snapshotted. M4B list values are joined with ", ". The M4B `.partial` is created with `CreateNew` and ffmpeg runs `-y` on it, because ffmpeg 9 exits 0 when `-n` refuses.
- 2026-10-19 (developer, slice 56): the two test-host flakes (health, scan service) were fixed, not accepted: test hosts run the processing worker only with `RunProcessingWorker`.
- 2026-10-19 (developer, slice 55): the BookPage section-load flake was fixed (`waitFor`), not accepted.
- 2026-10-19 (developer, slice 49): one intermittent backend failure, test unidentified (72 reruns passed; a stalled 34 s run), is accepted as a flake. Test runs keep full output (TRX) so a repeat names the test, which then gets fixed.
